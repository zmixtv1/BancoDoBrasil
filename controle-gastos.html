› As regras do jogo
  1. Uma coisa nova por vez. Cada fase adiciona no máximo uma tecnologia desconhecida.
  2. Sempre ter algo funcionando. Passo pequeno que roda > passo grande que não.
  3. Fatia vertical, não camada. "Cadastrar lançamento" inteiro antes de começar "editar".
  4. Teste a API sozinha antes da tela. Evita caçar no front um bug que está no Java.

Não fazer agora: gráfico bonito, login completo, refatorar antes de funcionar, "deixar preparado para o futuro".

› Quando travar
  1. Qual camada? Chame a API com curl. Se responde certo, o bug é no front.
  2. O que diz o log? docker compose logs -f api. A causa está na 1ª linha do erro.
  3. Funcionava antes? git diff mostra o que você mexeu.
  4. É ambiente ou código? Certificado, porta ocupada e falta de memória parecem bug — não são.
